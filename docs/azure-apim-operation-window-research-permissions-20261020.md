This is an unregistered research proposal. It is **not recommended for CSPM admission**: operation identifiers and the breadth threshold are customer analysis criteria, and the provider does not define a universal abuse threshold. No connector or default scan currently enables this proposal.

The research bridge requires its exact named check, `azure.review.apim.selected_operation_breadth_anomaly`, `log_observation_scans: true`, and one to three `selected_azure_apim_operation_windows` entries. Each entry contains an exact APIM `resource_id`, exact same-subscription `workspace_resource_id`, two to 32 distinct `operation_ids`, and integer `threshold_percent` from 1 to 99. Selectors and consent are validated before credential discovery. Kinds, framework selection and wildcard checks do not authorize reads. These parameters must not be turned into required customer policy for an automatic posture check.

Each selection performs four read-only operations:

| Native operation | Permission and purpose |
| --- | --- |
| ARM subscription GET,2022-12-01 | `Microsoft.Resources/subscriptions/read`; bind selected subscription and authenticated tenant. |
| Exact APIM service GET,2024-05-01 | `Microsoft.ApiManagement/service/read`; bind selected APIM ID, type, name and successful provisioning. |
| Exact workspace GET,2025-07-01 | `Microsoft.OperationalInsights/workspaces/read`; obtain the native workspace `customerId`. |
| Logs v1 query POST on that customerId | `Microsoft.OperationalInsights/workspaces/query/read` plus access to `ApiManagementGatewayLogs`, using the applicable workspace/table RBAC model. Granular RBAC uses `Microsoft.OperationalInsights/workspaces/tables/data/read`; legacy table access can use `Microsoft.OperationalInsights/workspaces/query/ApiManagementGatewayLogs/read`. Existing table/row restrictions still apply. |

ARM Reader alone does not establish access to workspace query data. The SDK credential requests `https://management.azure.com/.default` and `https://api.loganalytics.io/.default`; native requests use only `management.azure.com` and `api.loganalytics.azure.com`. No grants, workspace keys, writes, diagnostic-setting changes, search jobs, saved searches or alert rules are created. Existing authentication must support both audiences.

The fixed query covers the hour ending at capture time. It filters native resource, subscription, workspace and selected operation IDs, then calculates exact per-caller distinct operation counts and returns only aggregate counts and timestamps. It never projects caller IPs, request/response bodies, URLs, headers or credentials. No query text, custom endpoint, extra workspace or time-window expression is accepted from the caller.

Budgets are twelve total reads, two MiB per response, eight MiB total response bytes and a 120-second cooperative deadline with at most ten seconds per socket operation. Responses and connections close on every path. Credential providers must honor their own SDK timeouts; the bridge cannot forcibly interrupt an external credential implementation. Pagination links are rejected and never followed: this query has at most one grouped result, and native partial/error/truncation results cannot establish completeness. Zero matching rows remain UNKNOWN. Table plan/retention/access restrictions that prevent this standard Logs query remain unsupported; no broader search API fallback is attempted.

PASS means only that the maximum observed breadth in matching visible ingested records did not exceed the explicitly selected threshold. It does not prove complete event ingestion, unrestricted table/row visibility, benign traffic, attack prevention, a configured detection rule or alert delivery. A legitimate caller can exceed the source heuristic, and abusive traffic can stay below it. The selected workspace is an observation location; this proposal does not assert that APIM diagnostic routing is configured to it.
