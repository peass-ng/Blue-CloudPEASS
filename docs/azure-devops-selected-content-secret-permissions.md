# Optional selected Azure DevOps source and pipeline literal inspection

This is an unregistered local proposal. Root must integrate the named check, optional inventory, selector validation and collection hooks before enabling it in the product.

Use `azure.review.devops.selected_content_secret_indicators` explicitly, set `content_secret_scans: true`, and supply `selected_azure_devops_content`. Default scans and broad inventory selections must exclude this content reader. The existing UI group is **Secrets**; no numbered compliance requirement is asserted.

Use the existing `compliance_parameters.azure_devops_git.subscriptions` owner binding and a separate `auth.devops_credentials` entry for exactly `https://dev.azure.com/<organization>`. The selected subscription must belong to the authenticated Azure tenant. This binding records customer applicability; it does not make DevOps repositories ARM resources or establish their authorization universe. ARM Reader alone cannot read DevOps source.

Provide an explicitly provisioned Azure DevOps PAT with **Code (Read)** and, for pipelines, **Build (Read)**, or the existing explicit bearer credential issued for Azure DevOps. An ARM bearer token is not substituted for this credential. The reader does not obtain, inspect, verify or exchange tokens and does not follow a custom server or returned URL. Minimum project permissions are **View project-level information**, selected repository **Read**, and selected pipeline **View build pipeline**. Do not grant Contribute, Queue builds, Edit pipeline, variable-library administration, secret retrieval or run permissions for this reader.

Git selectors contain exactly `surface: "git_file"`, `scope`, `organization`, `project_id` (GUID), `repository_id` (GUID), `commit` (40 lowercase hexadecimal characters) and an absolute repository `path`. Pipeline selectors contain exactly `surface: "pipeline"`, `scope`, `organization`, `project_id`, positive integer `pipeline_id`, positive integer `definition_revision` and a 40-character `commit`. Scope and project must occur in the explicit owner binding. A pipeline pin inspects its selected historical definition revision and its native AzureRepos YAML file at the selected commit; it does not assert that commit was built or is the default branch head.

The only DevOps operations are GET, API version 7.1:

- `/{organization}/{projectGUID}/_apis/git/repositories/{repoGUID}` to verify repository/project identity and the embedded native project state. The selected pipeline definition also binds its embedded project identity; no separate Core project read or project enumeration is performed.
- `/{organization}/{projectGUID}/_apis/git/repositories/{repoGUID}/items` for one exact path with `includeContent=true`, `includeContentMetadata=true`, `recursionLevel=none`, `resolveLfs=false`, `download=false`, `$format=json`, and a commit version descriptor. Content must be UTF-8 text, a nonsymlink blob, and match the returned Git blob object ID and requested commit/path.
- For a pipeline only, `/{organization}/{projectGUID}/_apis/build/definitions/{pipelineID}?revision=<selectedRevision>`. Its native `TfsGit` repository and YAML process filename resolve the single Git item. Only configured variables explicitly marked `isSecret: false` are inspected; protected variables and library values are never requested. Unknown flags, masked values, references, variable groups or unsupported YAML prevent clean completeness.

No lists are needed: unexpected continuation headers/fields are rejected, rather than changing the selected universe. No clone, directory traversal, build/preview/run request, PR, logs, protected variable/library endpoint, LFS resolution, external template fetch, secret reference resolution, source execution or credential validation occurs. Provider-returned `url` and download URLs are ignored.

Local limits are eight selections; 24 DevOps GET attempts plus at most eight owner-subscription read invocations (the existing native cache can reuse those metadata reads); 2 MiB per response and 8 MiB in total, with at most one overflow-detection byte; 256 KiB of selected UTF-8 content per selection; 32 configured variables plus one selected file; and 120 seconds for this reader. Existing reader budgets and cancellation also apply. Each socket timeout is capped at ten seconds. Each offline detector receives at most half the remaining bounded time slice; no content is written to temporary files by this reader.

Both pinned offline engines, Kingfisher 1.4.0 and TruffleHog 3.92.5, must complete for PASS. A completed engine's bound hit remains FAIL when the other engine or a later selected read fails, with incomplete coverage shown. Unsupported, unreadable, malformed or unbound evidence cannot establish a clean result. Matching values are hidden, deduplicated using a process-local HMAC and scrubbed in union from output metadata; raw source, response bodies, error text, selected locators and credentials do not enter this reader's shared caches or findings. Python-managed transient buffers are released; memory zeroization is not claimed.

Coverage is only the explicitly selected visible file commit and selected definition's returned nonsecret literals. A mask or secret reference does not prove absence; recognized masks and dynamic-reference syntax prevent a clean result. Files outside the selectors, templates, variable libraries, runtime expansions, hidden content, repository history and other pipelines remain outside the result.

The separate Core Projects GET requires `vso.project`/`vso.profile`, so this reader deliberately uses the embedded project facts instead of requesting those extra scopes.

Official contracts: [Git Items GET 7.1](https://learn.microsoft.com/en-us/rest/api/azure/devops/git/items/get?view=azure-devops-rest-7.1), [Repository GET 7.1](https://learn.microsoft.com/en-us/rest/api/azure/devops/git/repositories/get-repository?view=azure-devops-rest-7.1), [Build Definition GET 7.1](https://learn.microsoft.com/en-us/rest/api/azure/devops/build/definitions/get?view=azure-devops-rest-7.1), [YamlProcess](https://learn.microsoft.com/en-us/javascript/api/azure-devops-extension-api/yamlprocess), [Azure DevOps permission reference](https://learn.microsoft.com/en-us/azure/devops/organizations/security/permissions-access?view=azure-devops).
