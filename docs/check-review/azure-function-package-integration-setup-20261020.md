The default-off control `azure.review.function.selected_package_source_secret_indicators` uses the existing Secrets group and the normal `azure_function_package_portable_20261020` inventory. It checks text members of an explicitly selected ZIP after associating that exact owned Blob with the selected Function/App Service site's configured `WEBSITE_RUN_FROM_PACKAGE` reference. It describes the configured captured package; executed/cached application bytes and continuous immutability remain unknown.

Enable `content_secret_scans: true` and name this exact public check. Set `selected_azure_function_package_sources` to one or two objects containing `site_resource_id` and `blob`, where `blob` contains `service: "blob"`, an exact storage-account `resource_id`, `container`, ZIP `object`, `format: "zip"`, and optional `version`. Use one to eight exact lowercase `/subscriptions/<GUID>` scopes. Slots, wildcard scopes, arbitrary URLs, non-Blob sources, shared service-account execution, and unsupported hosting are not inspection grants. Categories, frameworks, internal inventory names and serialized grant-like objects do not authorize source reads.

Grant only the optional read actions required on the selected subscription/site/account/blob: `Microsoft.Resources/subscriptions/read`, `Microsoft.Storage/storageAccounts/read`, `Microsoft.Web/sites/read`, `Microsoft.Web/sites/config/list/action`, and `Microsoft.Storage/storageAccounts/blobServices/containers/blobs/read`. The application-settings POST is Microsoft's documented read operation. The collector uses owned ARM and Blob OAuth access; it does not use the SAS returned in a package reference, retrieve account keys, resolve secret stores, contact Kudu, change roles, execute/build code, or validate detected credentials.

Each target has nine bounded operations: subscription/account metadata, site/settings before, Blob properties/content/properties, then settings/site after. Limits include two targets, eighteen native calls, a 120-second native deadline, 512 KiB ARM responses, 4 MiB per compressed object, 12 MiB aggregate native bytes, 1 MiB per text member, 8 MiB expanded per archive, 16 MiB expanded overall, and 128/256 members per archive/overall. Existing owner call budgets, cancellation and deadlines also apply. Unsupported nested archives, incomplete detectors, denied/malformed native responses and association/version changes produce UNKNOWN unless an already associated inspected member provides a decisive positive.

Both installed offline detectors must complete for PASS. A decisive partial positive remains FAIL with incomplete coverage. Public one-secret dedup retains the original matching package member's detector parts and source assertion provenance; it never constructs new engine parts from a merged detector list.

Live collection retains independently generated selection/tenant/customer/credential/capture locators through the owner channel. Ordinary CLI collection and JSON replay need no companion state or custom criteria: offline results validate self-contained snapshot coherence and label `context_provenance: supplied_snapshot_assertions`, `cloud_authenticity: not_established`, and the existing collector-assertion trust boundary. This is ordinary supplied-snapshot evidence, not independent native context or cloud authentication; replacing an entire coherent assertion dataset can fabricate facts as for other offline CSPM snapshots. Missing or inconsistent binding is UNKNOWN. Offline metadata never grants credentials or downloads. The original pure portable API still accepts a separately retained expected context for callers that need that stronger context boundary.

All actual native captures are exported to normal JSON before the process-local native seal is discarded. Match values from package and sibling selected readers survive only transiently; their HMAC descriptors remain until Azure finalization, subsequent bulk overlays, and the outer engine options/output have all been scrubbed. Cleanup clears selectors, pending match descriptors, old match sets, response caches, tuple-key cache entries and transport tokens. Privacy bounds are 256 distinct matched values, 64 KiB per value, 256 KiB total matched-value bytes, 8 MiB scrubbed surfaces, 65,536 nodes, depth 32 and two million candidate windows; overflow or key collision withholds the export.
