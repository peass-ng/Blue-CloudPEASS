# Portable Kubernetes regression tests

Apply `portable-tests.patch` after the coordinator installs the grouped runtime sources and completes normal source admission. The patch adds only the three test files in `file-whitelist.txt`. It does not edit a runtime module, admission guard, historical receipt, or existing test.

Run from the integrated repository root with the Python 3.12 environment: `python -m pytest -q tests/test_k8s_selected_text_content_portable.py tests/test_k8s_literal_fields_portable.py tests/test_k8s_configmap_association_portable.py --junitxml=k8s-portable-tests.xml`. The command is for the final integrated root; these tests have not been reported as passing against the current root, which lacks the new runtime modules. The existing focused helper remains `tests/test_k8s_literal_secret_review_20261020.py`.

The selected text option is `selected_k8s_text_resources`, and the collector kind is `k8s_selected_text_content`. It is default off. Give the scanner `get` for only named Events, Ingresses, Gateways, and CustomResourceDefinitions where selected; the named routes are `/api/v1/namespaces/{namespace}/events/{name}`, `/apis/networking.k8s.io/v1/namespaces/{namespace}/ingresses/{name}`, `/apis/gateway.networking.k8s.io/v1/namespaces/{namespace}/gateways/{name}`, and `/apis/apiextensions.k8s.io/v1/customresourcedefinitions/{name}`. The CRD route is cluster scoped. No list, Secret, Pod exec, or cluster-admin grant is required by this reader.

The bounded selected text fields are top-level annotation names and values; Event message, reason, action, reporting component, and source component; Ingress rule hosts, HTTP paths, and TLS hosts; Gateway addresses and listener names or hostnames; and CRD group, names, version name, top-level OpenAPI description, and conversion webhook URL. UID and resourceVersion must agree across the two exact reads. The existing selected literal reader also covers Pod and controller template labels and annotations, container probe HTTP headers or exec commands, and lifecycle hook HTTP headers or exec commands. ConfigMap association follows only explicit selected workload references and named GETs; a reference alone is not evidence that content was read.

The tests use synthetic native responses and block network calls. They preserve selected positive, negative, missing, foreign, changed-version, malformed, tamper, bounds, partial confirmed leak, and separate-process ConfigMap cases. They assert that selected text clones `_evaluate_legacy` while the ConfigMap wrapper remains installed, so both checks can coexist through normal imports and registered callables.
