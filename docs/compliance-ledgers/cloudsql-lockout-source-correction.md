# Cloud SQL failed-sign-in protection: source correction v2

The original requirement remains CCC.RDMS.CN02.AR01: repeated failed login attempts must result in account lockout or rate limiting. The previous instance-level `failedAttemptsCheck` proposal is retained as historical provenance; it is not an actual instance API field. Version 2 uses the documented per-user `passwordPolicy.enableFailedAttemptsCheck` and positive integer `allowedFailedAttempts`. It requires neither an undocumented lock duration field nor an invented numeric maximum.

A configured positive is available for serving managed MySQL 8.0+ only when the instance password policy is explicitly enabled, the complete exact project/instance user read is successful, every observed identity has supported built-in authentication and configured lockout, and the entire API-visible roster equals an explicit dated customer-account responsibility decision. The roster is not an allowlist that can discard a bad account. Username and host are separate identity components.

Supply that normative decision through existing connector options `sw09_policy`, with `status=collected`, exact `scope=projects/PROJECT`, and `lockout_account_scopes` keyed by exact instance name. Each record requires nonempty `approved_by` and `evidence_ref`, timezone-aware `reviewed_at` and `expires_at`, `responsibility=customer-controlled-database-accounts`, and nonempty unique `accounts` entries containing exact `name`, `host`, and `type`. The approval must cover capture/evaluation time. Account tuples must equal the entire observed roster and every tuple must have `type=BUILT_IN`. This is an explicit operator scope/responsibility decision, not native evidence that all mysql.user or provider-internal accounts were enumerated.

Without valid scope approval, the evaluator reports only a bounded native configuration witness and UNKNOWN for the original requirement. Mixed IAM authentication, unobserved or extra accounts, stale/malformed approval, unsupported engine/version, replica policy ambiguity, denied/partial/foreign source or missing configuration remain UNKNOWN. Missing or disabled policy never implies FAIL because independent rate limiting may satisfy the original requirement. No guest authentication, failed-login attempt, credential validation or runtime lockout is performed.

Current source corrections are exposed in public description, evaluator version and remediation, while the prior signed SHA is explicitly historical. Frozen ledgers and compiled packs are not rewritten. Local fixtures are synthetic contract examples, not customer compliance or live provider receipts.
