## Spot checks and common findings

- The Kubernetes collector projects component flags from static Pod argv, not running process settings (`peaso/collectors/k8s.py:158-225`); component checks only prove declarations (`peaso/checks/k8s_ports_components.py:146-193`).
- `file_metadata` is operator-supplied read-only stat metadata, not an API-host filesystem read (`peaso/collectors/k8s.py:706-747`). Each file proposal now requires complete node and path coverage before PASS.
- Existing exact audit checks at `peaso/checks/k8s_ports_reference_config.py:45-48` reject larger safe values; existing >= checks at `peaso/checks/k8s_ports_components.py:34-36` match benchmark thresholds.
- The four MANUAL requirement families were retested: client certificate, ServiceAccount token, and bootstrap token *human use* cannot be inferred from API object inventory; NetworkPolicy objects do not prove CNI enforcement. They remain MANUAL for each applicable framework version.
- Admission policy objects are collected via read-only admissionregistration API discovery/list operations (`peaso/collectors/k8s.py:126-155,821-839`), but effective third-party policy coverage and exemptions need UNKNOWN unless complete.
- The unique proposed IDs were checked for behavior conflicts across versions; common IDs are reused, with version-specific certificate mode thresholds remaining distinct.
