## desc-aws-2.problems.json
- aws.c2b.directoryservice.shared_accounts_review: code never returns FAIL; a shared directory yields MANUAL (no trusted-account list), although the title asserts 'not shared with accounts outside a trusted list' and severity is medium.
- aws.c2b.docdb.snapshot_restore_not_all_exact: only an AttributeValues list exactly equal to ['all'] fails; a list such as ['all','222222222222'] (still public) passes. Faithful to Steampipe but weaker than the critical-severity intent; aws.c2b.docdb.snapshot_not_public_prowler covers it.
- aws.c2b.drs.region_has_job: fails every audited region without a DRS job, including regions with no workloads at all (no NOT_APPLICABLE path); expect broad noise outside DR-designated regions.
- aws.c2b.ecr.registry_automated_scanning: the '*'-filter test considers every rule, not only automated ones, so a MANUAL rule with a '*' filter plus a SCAN_ON_PUSH rule filtered to 'prod-*' passes although not all repositories are scanned automatically (title says 'scans all repositories automatically').
- aws.c2b.ecs.cluster_has_registered_instances: Fargate-only clusters (which never register container instances) always FAIL; acknowledged in remediation but there is no NOT_APPLICABLE path for them.
- aws.c2b.ecs.host_network_root_user: privileged containers are skipped (Prowler semantics), so a privileged root container in host network mode passes although it is the riskiest case; title says 'non-privileged containers' so this is by design but worth noting.
- aws.c2b.efs.policy_not_open_to_vpc_clients: the AccessedViaMountTarget test is applied to every statement (including Deny or non-public ones), not only to the public statements; a public statement conditioned on AccessedViaMountTarget alongside an unrelated unconditioned Deny still FAILs.
- aws.c2b.eks.cluster_security_group_present: ported from Prowler eks_cluster_network_policy_enabled but only tests clusterSecurityGroupId presence; it says nothing about Kubernetes network policies, so framework mappings to 'network policy' requirements are misleading.
- aws.c2b.eks.version_at_least_1_19: the 1.19 floor is far below any EKS-supported version (support starts well above 1.28 by 2026), so a cluster on an unsupported version such as 1.20 passes despite the 'latest Kubernetes version' framework mapping and high severity.
- aws.c2b.elasticache.cluster_public_subnet: a 0.0.0.0/0 route to a NAT gateway marks a subnet 'public', but NAT routes are the standard pattern for private subnets; category exposure overstates the risk and private clusters with NAT egress FAIL (faithful to the Steampipe query).
- aws.c2b.elasticache.rg_backup_retention_15: an omitted SnapshotRetentionLimit PASSes (Steampipe NULL semantics) even though AWS omission means backups are off; title 'retains snapshots at least 15 days' is contradicted for that case (the 7-day variant treats omission as 0 and FAILs).
- aws.c2b.elbv2.recommended_tls_policy: RECOMMENDED_POLICIES excludes the 2025-09 PQ policies (e.g. ELBSecurityPolicy-TLS13-1-2-Res-PQ-2025-09), which the remediation of aws.c2b.elbv2.insecure_ssl_ciphers and the REJECTED notes call AWS-recommended/console default, so a listener on the current AWS default policy FAILs this check.
- aws.c2b.emr.cluster_local_disk_cmk: FAILs EncryptionKeyProviderType AwsKms even with a customer-managed KMS key, while the remediation says 'Custom (or AwsKms with your key as required)'; remediation implies AwsKms is acceptable but the code fails it (documented as faithful to upstream).
- aws.cb.ram.shared_with_accounts_review, aws.cb.ram.shared_with_organization_units_review, aws.cb.ram.shared_with_organizations_review: the code never compares principals with a trusted list or returns FAIL; matching principals return MANUAL, contrary to titles that imply an automated trusted-list decision.
- aws.cb.rds.cluster_snapshot_shared_accounts_review, aws.cb.rds.instance_snapshot_shared_accounts_review: the evaluator never returns FAIL; any nonempty restore-share list returns MANUAL because no trusted-account list is configured.
- aws.cb.rds.aurora_backtracking_configured: a present BacktrackWindow of zero PASSes even though no actual backtracking is possible; the positive-window check catches zero.
- aws.cb.rds.ca_certificate_not_expiring_7_days: the code compares a truncated day component to seven; a certificate with seven days and some hours left can FAIL even though it has more than seven full days to expiry.
- aws.cb.lightsail.ssh_rdp_http_world_closed: the source and evaluator match toPort 338 rather than 3389 for RDP, so an ordinary 3389-3389 world-open rule can PASS despite the title and high severity.
- aws.cb.kinesis.retention_exactly_168h: retention longer than 168 hours FAILs although it preserves more replay history; this is source equality rather than a minimum.
- aws.cb.lambda.runtime_not_deprecated_list: the pinned LATEST list includes nodejs16.x and dotnet6 while newer unlisted runtimes become UNKNOWN; the title and remediation imply current support, but the code only recognizes static lists.
- aws.cb.neptune.snapshot_restore_not_all_exact, aws.cb.rds.cluster_snapshot_restore_not_all_exact, aws.cb.rds.instance_snapshot_restore_not_all_exact: exact ["all"] matching lets ["all", "account-id"] PASS even though the snapshot is still public; the Prowler variants catch membership.
- aws.cb.neptune.no_public_subnet_steampipe, aws.cb.rds.instance_no_public_subnet: the route test marks a subnet public when 0.0.0.0/0 points to a NAT gateway; NAT egress does not itself permit inbound Internet traffic, so exposure findings can be false positives.
- aws.cb.kafka.latest_version: the code treats the last collected ListKafkaVersions entry as latest, without sorting or comparing version numbers; a differently ordered API response can invert the result.
- aws.cb.rds.postgres_force_ssl_parameter: the predicate accepts Engine exactly sqlserver or postgres; real RDS SQL Server engine names include edition suffixes, so they are NOT_APPLICABLE here despite the source row and SQL Server implication.
