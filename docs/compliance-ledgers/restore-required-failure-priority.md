# Restore test failure priority

For `azure.other.backup_restore_evidence`, a complete approved restore-test registry,
current native job capture, and independently bound usable-data result establish the
scope of each observation. An explicit `Failed` result for a required timely test
is a violation even when another test in that same validated registry lacks its
usable-data outcome. The unknown outcome cannot certify recovery.

Missing per-test outcome or restored-data verification remains `UNKNOWN` when no
independent required failure is established. Foreign resource identity, capture,
native digest, contradictory explicit outcomes, and incomplete registry authority
remain unresolved for the entire evaluation. A failed native job alone does not
override a later independently verified required success.

The directed tests use inert local ARM-shaped responses and synthetic external
validation records. They do not assert that a live restore or usable-data test was
performed.
