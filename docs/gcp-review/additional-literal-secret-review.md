# Scheduler, App Engine and Workflows literal secret review

Three pure, unregistered candidates use the existing secrets group and the shared offline Kingfisher 1.4.0 and TruffleHog 3.92.5 adapters. They inspect returned literal configuration only, hide values behind common HMAC fingerprints, merge detector observations and support shared cross-check deduplication. No target is executed, message pulled, credential verified, code endpoint downloaded or managed secret read.

`gcp.review.scheduler_job.literal_target_secret_indicators` reuses existing native v1 job/location reads and the `scheduler_job` inventory. The [native Job schema](https://docs.cloud.google.com/scheduler/docs/reference/rest/v1/projects.locations.jobs) provides a target union: HTTP/App Engine headers and base64 bodies, or Pubsub attributes and base64 data. Maps are bounded strings, byte fields require canonical standard base64 and strict UTF-8, and omitted fields on a complete unmasked target mean empty literals. Unsupported binary/encoding, missing or ambiguous targets and incomplete projections yield UNKNOWN. The original collector scrub still runs; a small proposed wrapper restores names-only target fields already scrubbed before transport caching. Safe schedule/state, URI host/path, routing, topic and token configuration references remain. Query/userinfo, literal values, free-form descriptions/error text and native injected scanner markers do not enter the cache. Default behavior adds no reads and runs no detectors.

`gcp.review.app_engine_version.literal_environment_secret_indicators` uses the new default-excluded `app_engine_version_secret` inventory. The current service/version producers remain masked and partial. Only complete, unambiguous native source inventories authorize a dependent GET with `view=FULL&fields=name,id,envVariables,buildEnvVariables`. The [version schema](https://docs.cloud.google.com/appengine/docs/admin-api/reference/rest/v1/apps.services.versions) documents the two environment maps, and the [REST enum](https://docs.cloud.google.com/appengine/docs/admin-api/reference/rest/v1/VersionView) is **FULL**, despite FULL_VIEW in some method prose. A missing map means empty only within that exact authorized GET; a partial source list cannot prove emptiness. Tests and fixture exports exercise the real service-list → masked version-list → opt-in full env GET → collector envelope chain. Default version masks are unchanged.

`gcp.review.workflow.deployed_source_secret_indicators` uses the new default-excluded `workflow_source` inventory. Native location and workflow lists must complete within bounds before any source GET. The [Workflow resource](https://docs.cloud.google.com/workflows/docs/reference/rest/v1/projects.locations.workflows) contains `sourceContents`, deployment state and native revision. The [read-only get method](https://docs.cloud.google.com/workflows/docs/reference/rest/v1/projects.locations.workflows/get) accepts the discovered `revisionId`; the response must match project, workflow and that exact revision and be ACTIVE. Missing/empty source, unavailable state, mismatched revision, duplicates, foreign subjects and incomplete discovery are UNKNOWN. The assessment concerns the revision observed during discovery, without claiming it remains the latest at collection completion.

Each content read requires boolean `content_secret_scans=true`, an engine binding from an explicitly named check to its precise kind, and an explicitly requested project ID. Discovered, wildcard or organization projects do not authorize content. Dependent GETs also require a producer-authorized exact URL/parameter tuple. The proposed early transport dispatch validates these constraints before credentials/cache construction. Identity HTTP encoding and exact bounded Content-Length or successful Requests chunk framing are required. Raw errors and caller authentication never become evidence; content operations bypass the generic transport cache.

Limits are 512 KiB HTTP/response, 64 KiB literal value, 256 KiB scanned/resource, 1 MiB scanned/scope/kind, 128 pairs/map and 100 resources. Scheduler content reads stop after three pages per scope. Workflows allows three pages/list, 20 locations and at most 128 calls for the new inventory; App Engine likewise has a 128-call ceiling. A 60-second cooperative scope/kind deadline surrounds reads/scans, HTTP idle waits are at most one second and per-engine timeouts at most ten seconds. Native Workflow source additionally has a 128 KiB cap. Any limit, cancellation, framing failure or either tool failure yields UNKNOWN, including partially positive observations. Shared SDK locking and OS scheduling are not hard real-time guarantees.

FAIL means a supported likely secret appeared in a complete returned literal assessment; PASS means neither tool found a supported match on those surfaces only. Other metadata, target paths, generated authentication, Workflows user environment values, runtime expansion, managed secrets, arbitrary encoded content and other versions/history are outside these predicates. Numeric/canonical aliases and legacy domain-scoped App Engine IDs are not guessed. Native resource identities and safe references remain for ownership; arbitrary user-chosen identifier text is not universally certified free of secrets.

The focused tests cover pinned dual-tool positives on all Scheduler target variants, App Engine maps and Workflow source, negatives, one-value dedup, privacy, native producer coverage, masks/revisions, pagination, authorization, default metadata compatibility, denial, malformed inputs, framing, limits and cancellation. Shared Function/Logging review detector and transport-hook patterns are attributed in the test file. Exact results, primary-document fetch hashes and source hashes are in [the JSON review](additional-literal-secret-review.json). Nine source-produced PASS/FAIL/UNKNOWN item/index fixtures, sealed snapshots, engine-compatible native wrappers and receipts are exported under `/tmp/peasso-gcp-review-20261019/additional-literal-secret-proposals/runtime-cases.json`; historical fixtures are untouched.

Root still owns applying `shared-hooks.patch`, admitting callbacks, catalog/copy, permissions and engine selection/default-exclusion validation. No shared source was edited and no live cloud, deployment, build, whole suite or offensive workflow was run. This is bounded native behavior proof, not full semantic certification.

Remediation is service-specific: Scheduler uses native OIDC/OAuth for compatible targets or an intermediary workload; App Engine application/build tooling can retrieve needed values through [Secret Manager client libraries](https://docs.cloud.google.com/secret-manager/docs/reference/libraries); Workflows can use the [runtime Secret Manager connector](https://docs.cloud.google.com/workflows/docs/use-secret-manager). No fake native secret-reference substitution or universal mutation command is suggested. Each declaration contains two direct remediation sentences. These text-only refinements followed the 102-test run; all nine current-source native fixture pipelines were regenerated afterward.

Proposed evidence uses two direct sentences per candidate: “A likely secret was detected in the returned [surface]. The value is hidden; offline detection did not validate the credential.” Desired-state titles and exact evidence strings appear in each declaration.
