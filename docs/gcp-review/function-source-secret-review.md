# Function resolved source archive secret review

`gcp.review.function.resolved_source_archive_secret_indicators` inspects supported text members of an immutable source archive associated with an observed Function. Its desired state is “Function resolved source archive has no detected secrets,” in the existing secrets finding group. The normal explicit `install()` loads source-produced compressed PASS/FAIL/UNKNOWN CASES; root owns registry import and canonical admission; installation was reported during review.

The [Functions v2 schema](https://docs.cloud.google.com/functions/docs/reference/rest/v2/projects.locations.functions#SourceProvenance) describes fixed source provenance and resolved storage generations. An omitted configured generation selects latest, so it cannot alone support a clean result. The adapter requires a matching configured bucket/object and a positive resolved generation, retaining the observed Function name and update time. A configured generation must match or be omitted/the documented upload placeholder zero. [Upload documentation](https://docs.cloud.google.com/functions/docs/reference/rest/v2/projects.locations.functions/generateUploadUrl) describes ZIP and that zero placeholder, while the StorageSource schema describes tar.gz. The implementation records this distinction and limits its claim to the referenced bytes. It never generates or reads an upload URL.

Only literal boolean `content_secret_scans=true` and the exact named check’s private `function_source_archive` binding authorize this inventory. No extra content requests occur by default. Existing native Function, CRM v3 project and bucket producers must complete. Functions must be ACTIVE GEN_2, with the exact selected project and native function identity. Cross-project buckets, repositories/Git, missing generations or provenance, ambiguous subjects and unsupported sources remain UNKNOWN.

The native pre-cache hook replaces source alternatives with an opaque reference and drops arbitrary descriptions/labels. Removed `buildConfig.source` and `sourceProvenance` receive nested UNKNOWN coverage with the static reason `function_source_reference_not_retained`, so omission cannot prove an absent setting. Bounded raw object targets exist only in a private pending plan, consumed by the dependent job and cleared on failure/teardown. Persistent source/object IDs are opaque; raw object paths and archive filenames never enter new receipts or scan evidence. Native Function owner names remain available for triage. Arbitrary secret-bearing native identities or encodings are not universally certified absent.

The dependent job constructs a private trusted selection for the existing audited `gcp_selected_archive_secret_indicators` adapter, after native ownership validation through `gcp_selected_object_secret_indicators`. Caller options and named kinds are unchanged. The existing [GCS metadata/media GET](https://docs.cloud.google.com/storage/docs/json_api/v1/objects/get) reader pins generation and `ifGenerationMatch`, validates metadata/media generation, MIME and size, disables redirects, bounds streamed bytes and discards raw errors. No new HTTP/archive implementation, extraction, execution, credential verification or managed-secret read was added.

The shared archive reader supports strict UTF8 regular text in ZIP/tar/tar.gz, rejecting unsupported or nested/binary members and unsafe paths. Shared offline Kingfisher 1.4.0 and TruffleHog 3.92.5 produce common value fingerprints; one value repeated across text members, detectors and multiple Function owners becomes one finding with owner triage preserved. PASS means no supported match in that fully supported resolved archive. FAIL means a likely secret there. Neither outcome certifies deployed images, running revisions, runtime values, all code or current freshness.

Bounds include ten Functions across the transport, a 32 KiB private source plan, a 30-second cooperative budget from capture shared with selected-object/archive state, twenty shared archive/object calls, 1 MiB per object and 8 MiB total compressed reads. Existing archive expansion, member, path, ratio, global native call/deadline and cancellation limits also apply. These are cooperative limits, not hard real-time guarantees. Missing/incomplete native ownership or receipts, denied/malformed/truncated media, unsupported archives, exhausted budgets or either failed detector yield UNKNOWN; empty inventories do not invent passing resources.
