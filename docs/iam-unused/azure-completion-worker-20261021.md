# Azure unused IAM completion helpers

This worker added optional read-only helpers in `peaso/collectors/azure_unused_iam_completion.py` and source-bound evaluators in `peaso/unused_iam_azure_completion.py`. They are not registered or invoked yet. The source receipts retain exact tenant, credential capture, endpoint, audience, method, status and projected object IDs; pagination goes through the existing reader.

Decide whether to reuse the existing `azure.entra_user_recent_sign_in` check instead of installing a duplicate: it already uses `lastSuccessfulSignInDateTime`, but this helper adds explicit capture and source binding.
2. For `managed_identity`, call `collect_arm_assignments` once per selected subscription and `evaluate_managed_identity_consumers` for a user-assigned identity. Expose PASS only for exact declared resource assignments. Expose UNKNOWN for zero matches, including a complete subscription response, since another subscription or provider may consume the identity. A separate system-assigned identity needs a distinct resource-bound path; this helper does not classify it.
3. For each application registration, call `collect_federated_credentials(..., managed=False)`. For each selected user-assigned managed identity, call it with `managed=True`. Use `evaluate_federated_credentials` to retain issuer, subject and audience metadata. Configured credentials yield UNKNOWN for unused status; zero credentials yield NOT_APPLICABLE. Do not install a FAIL control for federated credential inactivity without credential-specific successful exchange telemetry and a proven observation interval.
4. Register only after adding native case fixtures, a signed source review, HackTricks membership and any independently justified compliance mapping. Existing native registration, API/CLI visibility, catalog and ledger changes belong to the coordinator. The added tests cover the isolated helpers, not that end-to-end registration.

## Source limits

Microsoft's [signInActivity definition](https://learn.microsoft.com/en-us/graph/api/resources/signinactivity?view=graph-rest-1.0) says `lastSuccessfulSignInDateTime` includes interactive and non-interactive successes but has not been backfilled before December 1, 2023. `lastSignInDateTime` counts attempts, including failures. The [inactive-user guidance](https://learn.microsoft.com/en-us/entra/identity/monitoring-health/howto-manage-inactive-user-accounts) documents the v1.0 `$select=signInActivity` roster and update lag; [user listing](https://learn.microsoft.com/en-us/graph/api/user-list?view=graph-rest-1.0) requires AuditLog.Read.All and Entra P1/P2 for sign-in activity. A missing successful timestamp is UNKNOWN, never proof of nonuse. Creation age alone is never used to fail a user.

The [ARM resource list](https://learn.microsoft.com/en-us/rest/api/resources/resources/list?view=rest-resources-2021-04-01) exposes `identity.userAssignedIdentities` and paginates at subscription scope. The [managed identity model](https://learn.microsoft.com/en-us/entra/identity/managed-identities-azure-resources/overview) permits a user-assigned identity on multiple resources. A positive assignment is a consumer, not an authentication event; zero matches cannot establish unused identity. Cross-subscription and unsupported-resource coverage remain open.

Graph [lists application federated credentials](https://learn.microsoft.com/en-us/graph/api/federatedidentitycredential-list?view=graph-rest-1.0) under each application with `Application.Read.All`; ARM [lists user-assigned managed identity federated credentials](https://learn.microsoft.com/en-us/rest/api/managedidentity/federated-identity-credentials/list?view=rest-managedidentity-2024-11-30) under each identity. These sources expose configured trust fields, not per-credential successful token exchange or last use. Read access denial, partial pagination and malformed or foreign identity evidence remain unresolved.
