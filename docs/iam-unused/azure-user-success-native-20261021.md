## Decision boundaries

The check reports FAIL only for an enabled user whose current ID is present in both a verified tenant `directory_user` projection and a complete Graph user-success receipt, with matching selected fields, and whose most recent recorded successful sign-in is older than 90 days. It checks the immutable receipt digest, scan credential and customer context, collection projection, source endpoint, and timestamp relative to the capture and any known creation date. Recent failed attempts cannot override the last successful date. A nullable creation date remains acceptable when a bound old successful timestamp itself proves the user existed then; a contradictory creation date becomes UNKNOWN.

Missing or unlicensed sign-in data, absent historical backfill, denied or partial pagination, changed roster projection, invalid continuation, foreign tenant/capture, future timestamp or success before known creation yields UNKNOWN or DENIED. Disabled users are NOT_APPLICABLE. The evidence summary is one to three natural lines and does not direct automatic account disablement.

Microsoft [documents the v1.0 user list and sign-in permission](https://learn.microsoft.com/en-us/graph/api/user-list?view=graph-rest-1.0): `signInActivity` needs explicit `$select`, AuditLog.Read.All and Entra P1/P2. The [user resource definition](https://learn.microsoft.com/en-us/graph/api/resources/user?view=graph-rest-1.0) says `createdDateTime` is nullable for some users created before June 2018. The [signInActivity definition](https://learn.microsoft.com/en-us/graph/api/resources/signinactivity?view=graph-rest-1.0) says `lastSuccessfulSignInDateTime` covers successful interactive and non-interactive sign-ins since December 1, 2023 without backfill; `lastSignInDateTime` includes failed attempts. Microsoft's [inactive-user guidance](https://learn.microsoft.com/en-us/entra/identity/monitoring-health/howto-manage-inactive-user-accounts) describes update lag and the distinction between attempts and success.
