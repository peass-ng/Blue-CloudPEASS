# AWS remaining IAM completion: all-account permission sets and credential limits

## Implemented helper

`peaso/collectors/unused_iam_aws_completion.py` reads complete paginated Organizations `ListAccounts`, IAM Identity Center `ListInstances` and `ListPermissionSets`, then `ListAccountsForProvisionedPermissionSet` without a filter and with both documented latest-provisioning filters. It checks `ListAccountAssignments` for **every** enumerated organization account, including accounts absent from the provisioning list. It binds instance partition, owner account, permission-set ARN, account ID, principal type and principal ID. Incomplete, denied, malformed, duplicate, foreign-scope and inconsistent provisioning-state reads cannot prove absence. An account assignment remains a positive structural consumer if an unrelated read fails.

`peaso/unused_iam_aws_completion.py` decides one permission set at a time. `PASS` means a captured assignment or provisioned account; `FAIL` means complete all-account reads found neither; `UNKNOWN` means absence was not established. Its evidence is three natural lines and makes no permission-use or safe-deletion claim. This is **not** the existing `aws_identity_center_sso_configured` check, which evaluates account-local authentication configuration and user status.

The helper requires the Identity Center **home region**, the instance owner account context, permission to list organization accounts, and permission to read the instance and its account assignments. The `ListAccountsForProvisionedPermissionSet` status values are `LATEST_PERMISSION_SET_PROVISIONED` and `LATEST_PERMISSION_SET_NOT_PROVISIONED`; these say whether the latest permission-set version was provisioned to a listed account. A provisioned account remains a structural consumer even with zero captured principal assignments. The helper cannot prove absence for an organization it cannot enumerate, an instance in another home region, or an account outside its captured organization.

AWS API sources: [ListAccountsForProvisionedPermissionSet](https://docs.aws.amazon.com/singlesignon/latest/APIReference/API_ListAccountsForProvisionedPermissionSet.html), [ListAccountAssignments](https://docs.aws.amazon.com/singlesignon/latest/APIReference/API_ListAccountAssignments.html), [ListPermissionSets](https://docs.aws.amazon.com/singlesignon/latest/APIReference/API_ListPermissionSets.html), [Organizations ListAccounts](https://docs.aws.amazon.com/organizations/latest/APIReference/API_ListAccounts.html).

[The AWS object](https://docs.aws.amazon.com/IAM/latest/APIReference/API_ServiceSpecificCredential.html) contains no last-used value. | Do not label an old active credential unused from creation or expiration metadata. Role trust policies alone cannot establish provider-wide inactivity, including external session paths. |

## Existing credential-report control correction

`evaluate_credential_report` in the completion evaluator provides strict replacement decisions for the existing 45-day active-key and 45/90-day enabled-credential checks. It requires the source `ReportGeneratedTime` retained by the native collector, a matching account/user ARN, a timezone-aware snapshot clock no more than four hours later, user creation, enabled states, and each enabled credential's current date and last-use value. It reports a specific password or access-key slot and recorded last-use date. A stale, bound positive can survive another field's uncertainty; `PASS` requires every assessed enabled credential to have recent recorded use. A new credential with no recorded use remains `UNKNOWN`, and an inactive credential is excluded explicitly.

AWS documents that an active access key's `N/A` last-used value can mean never used **or** no recorded use since tracking began on 22 April 2015. A password's `no_information` can mean never used **or** no sign-in data since tracking began on 20 October 2014. The helper treats these markers as bounded no-use observations only when the current credential date is after the relevant tracking start and older than the selected interval; an earlier date, missing date, `not_supported`, or a marker on the wrong field stays unresolved. A report's `GeneratedTime` is the source clock, and AWS can reuse a report for up to four hours. [Credential report format and history](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_credentials_getting-report.html), [GetCredentialReport response](https://docs.aws.amazon.com/IAM/latest/APIReference/API_GetCredentialReport.html).

## Exact integration handoff

1. Load `peaso.collectors.unused_iam_aws_completion` as an AWS metadata extension in the root-owned collector registration. Its `SPECS`, `READ_ACTIONS`, `NATIVE_IDS`, and `FETCHERS` expose the native `aws_identity_center_permission_set_consumer` resource and `fetch(requests, session, region, account)` adapter. Request it once in the Identity Center home region from an authorized Organizations management/delegated context. Preserve the top-level `ReadResult` and each row's status, reason, provenance, and organization account universe. Do not merge this into `aws_identity_center_native`, whose account-local contract is different.
2. Add `from peaso.unused_iam_aws_completion import install as install_aws_completion; install_aws_completion(registry)` after the existing AWS unused-IAM routing call. The registrar installs a separate Hardening permission-set check with bound current scope and collection projection, then replaces the evaluator for the three existing credential-report IDs. Its packaged `peaso/checks/unused_iam_aws_completion_cases.json` and `unused_iam_aws_completion_credentials_cases.json` carry PASS/FAIL/UNKNOWN fixtures, with source review in `unused_iam_aws_completion_review.json`. Root still adds HackTricks membership, typed finding metadata, catalog descriptions and normal API/CLI fixture coverage in the owned catalogs and ledgers.
3. Add native credential inventory collectors only under a separate accepted scope: `ListUsers` plus per-user `ListSSHPublicKeys`/`ListSigningCertificates`, and account-global SAML/OIDC list APIs. Bind owner/account, paginate fully, omit signing certificate bodies and provider metadata documents, and report partial reads. Do not register an unused-credential inactivity check until successful-use authority is available; federation provider consumer absence may be assessed structurally with complete role trust-policy inventory.
4. Replace `aws.a.iam.unused_credentials_45_days` and `_90_days` decisions with `evaluate_credential_report(item, index, days=45/90, include_password=True)`; replace `aws.gap.iam.active_keys_used_within_45_days` with `include_password=False`. Keep existing IDs and source-compliance mappings, but update fixtures, descriptions, and Hardening registration as appropriate. The current collector already copies `GeneratedTime` into each CSV row as `ReportGeneratedTime`; root should preserve that field and complete collection status. The replacement emits `UNKNOWN` for incomplete report evidence and `MANUAL` for root account, rather than falling back from missing use to creation age.

The helper and focused tests are implemented; root integration and live AWS authorization/region validation remain open.

The native credential-report enricher records the actual read time and scan start. A report generated during collection is assessed against that bound read time, rather than rejected because the snapshot timestamp is the scan start. Reports outside the documented four-hour generation window or a mismatched capture remain unresolved.
