# GCP unused network objects: native-source disposition

This review concerns declared attachment or provider-reported current membership. It makes no claim about packet traffic, historical activity, future intent, or safe deletion. The baseline catalog had no GCP unused-network controls; this extension adds the source-supported observations below. Existing firewall exposure, logging, and VPC configuration checks are separate semantics; their exact IDs are in `peaso/rulepacks/native_catalog.json`.

| Family | Disposition | Evidence boundary |
|---|---|---|
| IP addresses | New `gcp.network.address_reserved_without_users` | Compute address `status=RESERVED` and empty `users` on a full, source-bound item. `IN_USE` with a user is PASS; inconsistent or reserving state is UNKNOWN. |
| Firewall policies | New `gcp.network.firewall_policy_without_associations` | Project network policy `associations` on a full, source-bound policy item. Organization/folder policy inventory is present separately, but this check does not project it into a project result. |
| Network endpoint groups | New `gcp.network.endpoint_group_without_endpoints` | Compute `size=0` for applicable NEG types; managed serverless and PSC endpoint types are excluded. A group may still be attached to a backend service. |
| HTTP/HTTPS target proxies | New positive-reference controls `gcp.network.http_proxy_forwarding_rule_reference` and `gcp.network.https_proxy_forwarding_rule_reference` | Exact canonical references from global and regional forwarding rules establish a consumer. No local match is UNKNOWN because all possible cross-project consumers are not closed. |
| Backend services | New `gcp.network.backend_service_has_members` | Full native membership includes both backend groups and service bindings, including serverless/internet NEG group declarations. An empty member set is a configuration review finding, not proof of absent frontends or traffic. |
| VPC networks and subnets | Source-unavailable for a complete unused verdict | Instances, templates, GKE, service networking, serverless connectors, private services, peering, routes and cross-project consumers can refer to these. The selected project inventory cannot prove all consumer scopes absent. Existing `gcp.reviewed.network.no_default_vpc` judges default VPC configuration, not unused status. |
| Firewall rules and target tags | Source-unavailable for unused verdict | A rule may be effective through network scope, target tags or service accounts, and tags can apply to consumers outside the observed project. Unmatched tags in a partial instance list do not prove an unused rule. Existing exposure IDs such as `gcp.claude.firewall.public_ingress_without_target` judge rule breadth, not usage. |
| Routes, policy based routes, network and interconnect attachments | Source-unavailable for unused verdict | Declared next hops or attachment references do not establish whether a route carries traffic or whether a hybrid peer consumes an attachment. No complete cross-network route-consumer observation exists. |
| VM interfaces | Source-unavailable as a standalone unused object | Compute VM interfaces are nested in instance configuration; there is no independent connector inventory or detached-interface lifecycle comparable to a reservation. |
| Forwarding rules, target proxies, URL maps, backend services and buckets, service attachments | Source-unavailable for a whole unused verdict | A sound reverse-reference absence result needs complete local and cross-project LB/PSC consumer inventory with consistent URL identity. A backend service can also use service bindings while its `backends` list is empty. The existing connector does not prove all reverse consumers absent. |
| Service endpoints beyond Compute NEGs | Source-unavailable for unused verdict | The network catalog gathers numerous regional private service and mesh resources, but selected projects/locations do not close all possible producers and consumers. Empty traffic or missing telemetry is never treated as unused. |

The source-bound checks use the collector's unmasked Compute list item, project-bound `selfLink`, `_provenance.representation=full`, and an unfiltered successful GET receipt for that resource kind. A known attached address, associated policy, or nonempty NEG still passes when another collection is partial. Missing fields, receipts, identity, or source projection yield UNKNOWN; a missing whole inventory yields no resource-level PASS or FAIL. Evidence summaries contain three direct natural lines.

The common native installer and generated metadata include all six controls. Selected proxy checks request forwarding-rule dependencies; the collector appends the global forwarding-rule list to the regional inventory through its normal bounded reader. An offline native transport test verifies the merged collection reaches an actual proxy finding. Local implementation and tests do not establish production deployment or a live scan.

Reviewed primary sources: [Compute Address](https://docs.cloud.google.com/compute/docs/reference/rest/v1/addresses), [FirewallPolicy](https://docs.cloud.google.com/compute/docs/reference/rest/v1/firewallPolicies), [NetworkEndpointGroup](https://docs.cloud.google.com/compute/docs/reference/rest/v1/networkEndpointGroups), and [BackendService](https://docs.cloud.google.com/compute/docs/reference/rest/v1/backendServices). The exact response-body hashes for the three admitted checks are in the JSON sidecar.
