# Azure and Kubernetes unused network object review

This review concerns structural declarations in a read-only capture. None of the checks establishes traffic inactivity, deletion safety, or Kubernetes CNI enforcement. A complete empty inventory is distinct from a denied, partial, or omitted inventory; those states cannot prove absence. The new check metadata and SHA-256 hashes of official source pages are in [the sidecar](../network-audit/unused-network-provider-specs-20261021.json).

## Azure disposition

| Object | Disposition | Evidence and limit |
| --- | --- | --- |
| NSG | **Existing supported control** `azure_pci_1_2_8_39` in `compliance_new_azure.py`. No duplicate added. | Full NSG `properties.subnets` and `properties.networkInterfaces` references prove current association. The existing control does not prove rule traffic or reachability. [Microsoft NSG resource schema](https://learn.microsoft.com/en-us/azure/templates/microsoft.network/2023-09-01/networksecuritygroups). |
| Route table | **New supported structural control** `azure.network.route_table_has_subnet_reference`. | Full read-only GET `properties.subnets` proves declared subnet associations. Missing or malformed GET/inventory returns UNKNOWN. [Microsoft route table schema](https://learn.microsoft.com/en-us/azure/templates/microsoft.network/2025-07-01/routetables). |
| NIC | **New supported structural control** `azure.network.nic_has_owner_reference`. | Full read-only GET checks VM, private endpoint, private link service, and hosted workload owner fields. A detached NIC may be reserved for later use; the finding calls for owner review. [Microsoft NIC schema](https://learn.microsoft.com/en-us/azure/templates/microsoft.network/2023-09-01/networkinterfaces). |
| Public IP | **New supported structural control** `azure.network.public_ip_has_network_reference`. | The collector now requires a full resource GET. In Succeeded state, IP configuration, NAT gateway, linked/service public IP and prefix references are checked together. Missing or denied detail is UNKNOWN. An unreferenced reservation requires owner review before release. |
| Load balancer backend pool | **New supported declaration/consumer control** `azure.network.load_balancer_backend_pools_have_declaration_or_consumer`. | A full parent GET checks backend addresses, NIC IP configurations, load-balancing, outbound and NAT-rule consumers. A pool without any captured declaration or consumer requires owner review; an empty backend-address list alone does not fail. [Microsoft load balancer schema](https://learn.microsoft.com/en-us/azure/templates/microsoft.network/2024-07-01/loadbalancers). |
| Subnet | **New supported declaration/reservation control** `azure.network.subnet_has_consumer_or_reservation_reference`. | Full native child GETs inspect IP configurations, private endpoints, delegations, service association links, IP allocations and application-gateway references together. No captured declaration is a cleanup review candidate, not proof that every external or future platform consumer is absent. [Microsoft subnet schema](https://learn.microsoft.com/en-us/rest/api/virtualnetwork/route-tables/get?view=rest-virtualnetwork-2025-07-01). |

## Kubernetes disposition

| Object | Disposition | Evidence and limit |
| --- | --- | --- |
| Service | **New supported current backend declaration control** `k8s.network.service_has_current_backend_declaration`. | Selector-based Services match Pods in the same namespace and nonempty address declarations in EndpointSlices bearing `kubernetes.io/service-name`. An empty slice is not a backend. ExternalName and selectorless Services are NOT_APPLICABLE: they may use external or manually managed backends. Zero endpoints or zero selected Pods does not prove an unused Service. [Service documentation](https://kubernetes.io/docs/concepts/services-networking/service/). |
| Endpoints | **New conditional controller-owner control** `k8s.network.endpoints_controller_service_reference_resolves`. | Core Endpoints are collected read-only. Only endpoint-controller-managed objects with an explicit Service owner are evaluated against same-namespace Service name and UID. Custom unmanaged Endpoints are excluded. [EndpointSlice documentation](https://kubernetes.io/docs/concepts/services-networking/endpoint-slices/). |
| EndpointSlice | **New supported Service-reference control** `k8s.network.endpointslice_service_reference_resolves`. | Same-namespace Service-name label is resolved against complete native Service inventory; a declared Service owner UID must match. Unlabeled slices are not treated as unused because custom controllers may consume them. [EndpointSlice documentation](https://kubernetes.io/docs/concepts/services-networking/endpoint-slices/). |
| Ingress | **New supported backend-reference control** `k8s.network.ingress_service_backends_resolve`. | Native Service backends in default and HTTP path rules must resolve in the same namespace. Resource backends and controller defaults are outside this predicate. This is not proof the controller serves traffic. [Ingress documentation](https://kubernetes.io/docs/concepts/services-networking/ingress/). |
| NetworkPolicy | **New supported current selector control** `k8s.network.networkpolicy_selects_current_pod`. | `podSelector` is matched against same-namespace Pod labels, including an empty selector selecting all Pods in that namespace. No current match can be intentional for a future workload; CNI support and enforcement are not inferred. [NetworkPolicy documentation](https://kubernetes.io/docs/concepts/services-networking/network-policies/). |

## Native integration

The common unused-network installer registers these controls once. Hash-bound cases, catalog descriptions, priorities and HackTricks Cloud Best Practices `unused_assets` mappings are included. Azure subnet and load-balancer tests exercise actual read-only collector GETs through snapshot evaluation; Kubernetes tests exercise native Endpoints collection. This document describes local implementation, not a completed production scan.
