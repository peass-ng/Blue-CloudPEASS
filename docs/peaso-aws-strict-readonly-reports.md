AWS default collection reads existing IAM credential reports and never creates or refreshes provider-side report jobs. Missing, expired and pending credential reports produce `not_collected` with the original native reason, rather than an empty inventory or a new report. Existing CSV parsing and observation provenance remain unchanged.

Service-last-accessed report creation is disabled. IAM does not offer a list operation to discover an existing report job ID; without an independently supplied native job identity, per-principal usage evidence remains `not_collected`. `GetServiceLastAccessedDetails` stays permitted for an already-known job; this change does not invent a job binding or infer inactivity.

Both IAM Generate operations are also rejected by `Requests.call` before client creation, credential resolution or request accounting. Authorized STS credential exchange, metadata simulations, CloudTrail lookup, all enabled-region inventories and existing IAM metadata reads retain their prior contracts. The authorized Access Analyzer exception adds no new workflow or resources. A presentation process additionally installs the separately reviewed global SDK barrier, covering direct SDK calls outside `Requests`.
