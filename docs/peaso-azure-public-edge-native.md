# Native public-edge protection evidence: bounded initial batch

This private component supplies exact native ETag-bound bindings for the unchanged signed control `azure_application_gateway_11_5_1_1_1_f56bdc2`. It is not part of the published presentation source `475e4f00…` until independently reviewed and integrated.

The supported complete-control path is a selected Azure subscription containing Public IPs and load balancers, with authoritative complete empty inventories for Application Gateway and both Front Door generations. Complete native empty inventories also support a NOT_APPLICABLE result. Private gateways/load balancers with no public frontend can be resolved; public gateways remain UNKNOWN without effective listener/routing-rule WAF evidence.

All four existing ARM parent inventories must be complete, unique, scope-bound, and consistent. A second bounded native LIST rejects duplicates silently collapsed by the generic Reader and requires exactly the same resource membership. Native GETs provide the resource properties, identity, API generation and ETag; malformed/foreign/changed identities fail closed. Complete native CDN profile LIST/GET enumeration distinguishes documented classic CDN products from Azure Front Door Standard/Premium; unknown products fail closed. A populated Front Door inventory remains UNKNOWN in this initial batch rather than borrowing unsupported WAF or built-in DDoS assertions.

For every supported resource, the collector records its native ETag and exact public frontend IDs. A load balancer's frontend public-IP reference must resolve to the same subscription's complete Public IP universe. Each Public IP is evaluated separately, so a protected IP cannot cover a different frontend.

Explicit native Public IP `ddosSettings.protectionMode = Enabled`, without an attached plan, supports the signed IP-protection configuration path. Explicit Disabled fails. Absent settings, VirtualNetworkInherited, or an unresolved explicit plan remain UNKNOWN; this batch does not infer VNet inheritance or plan activation. The signed predicate supplies the protection requirement; no customer input may provide observed status or a manufactured protection binding.

The module uses read-only ARM metadata LIST/GET requests through the existing bounded Reader, applies the existing credential sanitizer explicitly, and performs no writes, traffic probes, authentication tests, provider fixtures, or privilege-escalation execution. It adds no dependency. Shared canonical resource replacements commit only after the complete scoped join succeeds; no partial favorable subset is published as complete.

The V2 `azure-hook.patch` imports the module, registers its two native types, expands native parent requirements and calls its collector immediately after the main parent inventory settles, before `azure_swc.collect_facts` and every diagnostic enrichment. Existing enrichment therefore attaches fresh diagnostic settings/categories and their coverage to the new native GET objects. No stale enrichment is copied across an ETag change. It must be merged with any other `azure.py` edits rather than replacing the full file. Product source in the shared workspace is untouched.

Directed tests exercise the native transport fixture, actual collector, snapshot seal and unchanged signed checker: PASS for complete protected IP/LB scope, FAIL for disabled IP protection, NOT_APPLICABLE for complete empty/private scope, UNKNOWN for unsupported/ambiguous/malformed evidence and bounded budgets, and DENIED for native forbidden responses. Native secret-like fields are redacted. The retained initial duplicate failure is corrected in the final 21-case run.

Native API references: [Public IP GET](https://learn.microsoft.com/en-us/rest/api/virtualnetwork/public-ip-addresses/get), [Front Door/CDN profiles LIST](https://learn.microsoft.com/en-us/rest/api/frontdoor/azurefrontdoorstandardpremium/afd-profiles/list). The code uses Network `2023-09-01`, classic Front Door `2021-06-01`, and CDN profile `2025-04-15`; it supplies no undocumented property defaults.

Remaining work includes complete public Application Gateway WAF precedence, classic and Standard/Premium Front Door endpoint/domain/security-policy joins, trustworthy product DDoS mappings, and exact inherited VNet/plan association. Neither type presence nor these configuration results prove actual mitigation efficacy or global CSPM completeness.

V2 changes only hook ordering and adds `tests/test_peaso_azure_public_edge_composition.py`: one actual combined collector case changes the native load-balancer GET ETag, discards deliberately stale list-only diagnostics, verifies newly requested diagnostic settings/categories and their collected coverage survive, checks request ordering, and retains a signed SW22 PASS.
