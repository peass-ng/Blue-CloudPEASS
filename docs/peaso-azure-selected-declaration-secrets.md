# Optional selected Azure declaration scanning proposal

These three readers are **unregistered proposals**. They are not exposed by the production connector yet. Root admission must add the exact named checks, selectors, collector hooks, default exclusions and presentation metadata together. Standard metadata scans do not authorize content reads.

A future admitted scan requires `content_secret_scans: true`, the exact named check and the matching native selector below. Select at most eight targets across the three options, in one to eight explicit subscription scopes. No store keys, factories, workspaces, pipelines or linked services are enumerated. Both pinned offline detectors must complete before a clean result; unavailable or incomplete negatives remain UNKNOWN. Detected values are hidden and are never validated.

| Proposed check | Option and exact target shape |
| --- | --- |
| `azure.review.app_configuration.selected_value_secret_indicators` | `selected_azure_app_configuration_values`: `[{"resource_id":"<configuration-store ARM ID>","key":"App/Mode","label":null}]`. A null label means the native unlabeled value; named labels and keys are case-sensitive. |
| `azure.review.data_factory.selected_declaration_secret_indicators` | `selected_azure_data_factory_declarations`: `[{"resource_id":"<factory ARM ID>/pipelines/<name>"}]` or a native `/dataflows/<name>` resource ID. |
| `azure.review.synapse.selected_pipeline_secret_indicators` | `selected_azure_synapse_pipelines`: `[{"resource_id":"<workspace ARM ID>/pipelines/<name>"}]`. |

Use an existing explicitly configured SDK credential capable of acquiring tokens for the required audiences. An ARM-only bearer token cannot authorize App Configuration or Synapse data-plane reads; no new bearer-token input or automatic credential fallback is proposed.

| Read | Required permission and token audience |
| --- | --- |
| Each selected subscription GET (`2022-12-01`) | `Microsoft.Resources/subscriptions/read`; ARM audience `https://management.azure.com`. The native subscription ID, enabled state and tenant must match the selected scope and authenticated tenant. |
| App Configuration store GET (`2024-06-01`) | `Microsoft.AppConfiguration/configurationStores/read` on the selected store; ARM audience. The native ID, type and name bind its native endpoint to `<store>.azconfig.io`. |
| Exact App Configuration `/kv/{key}` GET (`1.0`), followed by a same-ETag `If-Match` GET | App Configuration Data Reader on the intended store, including `Microsoft.AppConfiguration/configurationStores/keyValues/read`. ARM Reader does not grant data-plane access. This proposal pins `https://azconfig.io` / `https://azconfig.io/.default`, matching the public `azconfig.io` endpoint inference in Microsoft's Python SDK; no challenge-derived audience or alternate host is followed. |
| Exact ADF pipeline or dataflow GET (`2018-06-01`) | `Microsoft.DataFactory/factories/pipelines/read` or `Microsoft.DataFactory/factories/dataflows/read` on the selected resource; ARM audience. Existing ARM Reader includes these reads; no additional data-plane, run, write or linked-service permission is requested. |
| Synapse workspace GET (`2021-06-01`) | `Microsoft.Synapse/workspaces/read`; ARM audience. Native identity and `connectivityEndpoints.dev` bind the selected workspace's standard development host. |
| Exact Synapse pipeline GET (`2020-12-01`) | Synapse RBAC `Microsoft.Synapse/workspaces/artifacts/read`, e.g. Synapse Artifact User at the workspace, plus the metadata reads above; `https://dev.azuresynapse.net/.default`. Azure ARM Reader alone does not grant this artifact read. Artifact User also includes output-view permissions, which this reader does not use; do not grant a publisher, credential-user or administrator role for this scan. |

App Configuration scans only the selected non-Key-Vault literal value. Key Vault content types, encrypted content types and recognized platform reference values are excluded. No connection strings, access keys, snapshots or labels are listed. The complete native key/label pair, quoted header ETag, body ETag and repeated body must agree. Unknown, missing, changed or denied values cannot produce PASS.

ADF scans public pipeline activity `typeProperties`, public parameter/variable defaults and MappingDataFlow inline `script`/`scriptLines` plus visible source/sink/transformation declarations. Synapse scans the corresponding published pipeline inline declarations. SecureString/SecureObject, Key Vault references, protected settings, encrypted credentials and dataset/linked-service references are excluded. A visible hit remains FAIL when other coverage is incomplete; references or unsupported content without a hit remain UNKNOWN. Descriptions, pipeline execution results, linked services, datasets, Git-only drafts and external scripts are not covered. Nothing is executed or dereferenced.

The proposal caps each response at 2 MiB, all responses at 8 MiB, projected content at 256 KiB, calls at 32 and elapsed work at 120 seconds. Projection is bounded to 8,192 nodes, depth 24 and 2,048 literal strings. Native HTTP bodies bypass generic caches; errors discard native text. Request paths and selected identities are exported only as HMAC locators. Matched-value callbacks feed the existing bounded five-reader final union, and the new metadata ledger must be merged before that final scrub. These are local reader bounds, not proof of live reachability or exhaustive application content.

Exact selected plain files and bounded ZIP/tar artifacts already belong to the [selected Blob/File reader](peaso-azure-selected-storage-secrets.md). A deployment's public source reference can help an operator choose its known native storage object, but these readers never follow arbitrary URIs, SCM/publishing endpoints, Databricks/ML code links or protected source stores. A scanned stored object does not prove what code is deployed or running.

Log Analytics/Application Insights message sampling is **not implemented** in this batch. Existing Azure telemetry reads fixed aggregate counts, not message content. Reusing its generic request cache for message bodies would retain raw log values. A separate finite proposal needs a selected native ARM workspace/customer-ID or application/App-ID binding, a dedicated bounded uncached query reader, fixed table/column/time/sample policy, partial-result/error checks and matched-value redaction. No current metadata or aggregate result establishes secret-free logs, and a bounded sample could never establish all-history coverage.
