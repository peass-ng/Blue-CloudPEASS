# Selected Synapse published notebook source

`azure.review.synapse.selected_notebook_source_secret_indicators` is default off. Select that exact check, set `content_secret_scans: true`, and provide one to four `selected_azure_synapse_notebooks` entries before credential acquisition:

```json
{"workspace_resource_id":"/subscriptions/SUB/resourceGroups/RG/providers/Microsoft.Synapse/workspaces/WORKSPACE","notebook_name":"PublishedNotebook"}
```

The reader calls ARM subscription Get and [workspace Get](https://learn.microsoft.com/en-us/rest/api/synapse/resourcemanager/workspaces/get?view=rest-synapse-resourcemanager-2021-06-01), then the exact [Notebook Get API](https://learn.microsoft.com/en-us/rest/api/synapse/data-plane/notebook/get-notebook?view=rest-synapse-data-plane-2020-12-01) twice, then workspace Get again. It accepts only the workspace-derived `https://WORKSPACE.dev.azuresynapse.net` host and exact notebook name, ID, type, ETag and source-cell digest across both reads. It scans only `properties.cells[].source` strings. Outputs, attachments, metadata, Git branch content, runs, files referenced by cells and other notebooks are excluded. It does not list, execute, publish, mutate or follow URLs.

The existing identity needs `Microsoft.Resources/subscriptions/read` and `Microsoft.Synapse/workspaces/read` in ARM. Reading a published notebook through the development endpoint separately needs Synapse RBAC `Microsoft.Synapse/workspaces/artifacts/read`, for example a workspace-scoped **Synapse Artifact User**; ARM Reader alone is insufficient. The [Synapse RBAC role table](https://learn.microsoft.com/en-us/azure/synapse-analytics/security/synapse-workspace-synapse-rbac-roles) distinguishes published artifact reads from connected Git repository access. [Synapse REST authentication](https://learn.microsoft.com/en-us/rest/api/synapse/) requires a `https://dev.azuresynapse.net/` audience token for data-plane calls, separate from ARM. Both tokens must describe one tenant and principal.

The reader permits at most 20 native calls, 2 MiB per response, 8 MiB total wire data, 128 cells, 1 MiB source text and a checked 120-second deadline. A clean PASS requires complete owner binding, identical ETag/source across both reads and both offline detectors finishing. A bound likely-secret finding remains FAIL if one detector is unavailable. Denied, malformed, truncated, changed or incomplete clean content is UNKNOWN. The value stays private; HMAC leak identities merge in the existing transient redaction union and are cleared after snapshot finalization. A stable SHA-256 of the selected non-secret resource ID identifies the target across processes; it is separate from the random-key HMAC evidence fingerprints.
