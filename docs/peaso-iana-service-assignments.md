# Pinned IANA assignments for the Azure NSG service check

`azure.other.nsg_port_protocol_assignment` compares an externally supplied, authoritative `measuredService` with active IANA service names assigned to the effective path's exact TCP or UDP destination port. The local registry snapshot contains every active named TCP/UDP numeric assignment and expands the three named port ranges in the source. All active aliases are accepted. Rows without a port are not port assignments; absent active assignments and a conflicting `ianaAssignedService` claim leave the result UNKNOWN when the measured service otherwise matches. A measured service outside a known active assigned set conclusively fails, even when a mistaken `ianaAssignedService` field repeats it. Missing service measurements remain UNKNOWN.

Pinned source: [IANA Service Name and Transport Protocol Port Number Registry](https://www.iana.org/assignments/service-names-port-numbers/service-names-port-numbers.csv), HTTP Last-Modified `Fri, 16 Oct 2026 04:01:56 GMT`, CSV SHA-256 `b6afeefdc6b2c616f9a515d57819a558ebe33250b59b2700b3afc4a4ba1923f2`. The derived local mapping is `peaso/collectors/iana_service_assignments.json`, SHA-256 `c940764552e8542bb1e3b68c71a5f486afbb96f0fb4a91568c2594ec696c53c8`. Evaluation verifies the mapping hash once per process and performs no network access. A later IANA revision requires deliberate regeneration and review; this pin makes no claim about future assignments.

The CSV was reviewed row by row for named TCP/UDP ports. Its explicit non-active descriptions exclude `sua` on UDP/14001 (`De-Registered`) and `stun-behaviors` on UDP/5349 (`Reserved for a future enhancement of STUN-BEHAVIOR`); both rows remain visible in the derived artifact's `excluded_inactive` list. [RFC 6335 §8.2](https://www.rfc-editor.org/rfc/rfc6335.html#section-8.2) explains that de-assigned port numbers become reserved and historical names or comments may remain. `sua` on TCP/14001 remains active, as do the other UDP/5349 aliases. The `RemoteWare Unassigned` description on TCP/UDP 2999 is a service description, not an explicit lifecycle status, so its `remoteware-un` assignment remains active. These exact classifications describe this pinned revision only.

The mapping states registry names only. It does not observe workloads or provide a native service measurement. PASS still requires the existing complete effective-path and authoritative external measurement contract.
