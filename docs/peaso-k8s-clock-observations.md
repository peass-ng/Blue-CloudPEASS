# Kubernetes externally reviewed clock observations

The clock control accepts an optional `options.node_clock_evidence` import. It performs no proxy request, host command, exec, privileged workload or clock probe. Kubernetes Node and Namespace LISTs bind the supplied measurements to current node UIDs and the current `kube-system` UID. A complete `*` cluster scope is required. Missing, stale, foreign, partial or unreviewed evidence remains UNKNOWN; native inventory authorization denial remains DENIED.

The object contains `review` and `observations`. The review contains exactly `cluster_id`, `kube_system_uid`, `reviewer_id`, `review_record_id`, `reviewed_at`, `max_age_seconds` (1–600), `approved_observer_ids`, `approved_reference_ids`, and `reviewed_measurement_ids`. The last three fields are nonempty unique bounded lists of identifiers. Use real independent review records and measurement identifiers; the importer does not retrieve or authenticate those external records.

Each observation contains exactly `node_name`, `node_uid`, `measurement_id`, `observer_id`, `reference_id`, `measured_at`, `node_utc`, `reference_utc`, `uncertainty_seconds`, `node_measurement_method`, `node_identity_record_id`, `reference_protocol`, and `reference_verification_record_id`. Timestamps require timezones. Supported measurement labels are `host_agent_clock_read` and `validated_kubelet_tls_date`; reference labels are `NTS`, `PTP-authenticated`, and `GNSS-disciplined`. These labels identify the externally reviewed evidence, and do not cause CSPM to verify a TLS exchange, NTS authentication or GNSS accuracy. Never supply these records when actual source/reference verification is unavailable. No signature, certificate, credential, command output or secret belongs in this input.

Every current node must have one distinct reviewed measurement and UID. Review and capture timestamps must be fresh and not in the future. Reference UTC must agree with the measurement capture within the supplied finite uncertainty (0–60 seconds). The normal `compliance_policy.approved_clock_skew` remains mandatory, with its existing cluster binding and freshness checks. A measurement interval entirely within the approved skew passes; one entirely outside fails; an interval crossing the threshold remains UNKNOWN.

The report explicitly labels this path `externally_reviewed_measurements`, with `native_clock_verified=false` and `external_authenticity_independently_verified=false`. Its verdict applies to the supplied measurements under the operator's review. It is not independent physical clock verification or new native clock collection. Native proxy-based evidence retains its existing separate requirements. The importer rejects caller-supplied `node_response_verified`, `trusted_clock_verified`, native `source_operation`, and other unknown fields rather than laundering them into native facts.
